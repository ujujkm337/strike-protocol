# Статус — 14.09, после раунда «игра не запускалась в бою»

## Что было сломано (найдено, а не угадано)

Пользователь нажал Quick Match и увидел чёрную полосу + мёртвый ввод. Причина —
не одна, пять независимых, и все были невидимы для `--check-only` и для
прежних headless-тестов:

1. **`Player` без `script=`** в `scenes/maps/bench.tscn` — контроллер вообще не
   висел на игроке. Ни WASD, ни мышь, ни `move_and_slide`.
2. **Спавн (0, 1.2, 0) лежал ВНУТРИ стены** `DoorDoubleLongWallSideAMesh_51`:
   зонд показал «0 из 9 секторов обзора свободны», полигон в 0.21 м от глаз.
   Это и была чёрная полоса (backface-кулинг: видно внутреннюю, неосвещённую
   сторону).
3. **`@onready var camera = $Head/Camera3D` при узле, названном `Camera`** →
   `camera == null`, `_ready()` падал на первой строке, и `Mouse mode CAPTURED`
   + `camera.current` никогда не выполнялись.
4. **`e.is_action_pressed("crouch")` внутри `_unhandled_input`** — у
   `InputEventMouseMotion` этого метода нет, на первом же движении мыши скрипт
   падал, присед/пауза не работали никогда. Плюс `is_action_pressed` (не `just_`)
   переключал присед каждым кадром удержания.
5. **`@export var player_body / camera` c `NodePath("../../..")` из .tscn не
   резолвятся** → `weapon.player_body == null`, hitscan не исключал стрелка.
   Теперь пути разрешаются в `Weapon._ready()` обходом вверх по дереву.

## Что сделано

* `bench.tscn`: `script=ExtResource("90")` на Player, группа `player`,
  `spawn_path=../SpawnCT`, спавны CT/T перенесены в замеренные чистые точки
  `(-16, 1.2, -8)` / `(16, 1.2, 8)`, маркеры развёрнуты лицом к центру карты,
  `Head` = 0.82, `Camera3D` переименован из `Camera`, добавлен `HUD`.
  **Внимание: `bench.tscn` генерится `tools/build_bench.py`** — при следующей
  перегенерации эти правки надо внести в генератор, иначе они исчезнут.
* `fps_controller.gd`: `_find_camera()` (по имени и по типу), `_apply_look()` —
  единственный владелец ориентации (`rotation.y = _yaw`, `head.rotation.x =
  -_pitch`, камеру не крутим), мышь накапливается в `_unhandled_input` и
  применяется раз за кадр, клавиши читаются в `_physics_process` через
  `Input.*_just_*`, `_try_crouch()` проверяет свободу перед вставанием,
  `eye_height_stand/crouch` = 0.82/0.20 **от центра капсулы**.
* `weapon.gd`: удалена запись `camera.rotation.x` в `_apply_recoil()` — она
  накладывалась на −90° каждый кадр (замер: −5156.6°); добавлен резолв
  `camera`/`player_body` в `_ready()`.
* `scenes/ui/hud.tscn` + `scripts/ui/hud.gd`: прицел, название оружия, патроны,
  индикатор «МЫШЬ НЕ ЗАХВАЧЕНА», захват по клику/нажатию клавиш (нужно для
  браузера, где pointer lock теряется).

## НЕ проверено (важно)

* **Запуск `.exe` на Windows** — в песочнице нет ни Windows, ни wine, ни GPU.
* **Реальный рендер** — GPU недоступен, картинку глазами не видел никто из нас.
* **Покой игрока на полу.** Три прогона дали противоречивые результаты: в один
  игрок стоял (`origin=0.95`, глаза 1.77, сдвиг WASD), в другом — пролетал пол,
  при том же содержимом сцены на диске. Причина расхождений — ненадёжность
  headless-харнессов здесь: в `-s`-режиме `Engine.get_physics_frames()` иногда
  не двигается, `global_position` детей отстаёт на кадр, а `CollisionShape3D`
  читался с `position.y = 0` вместо 0.9 из файла.
  **Если в собранной игре игрок тонет ногами в полу или падает сквозь карту —
  правка одна строка: смещение `Stand`/`Crouch` (0.9/0.55 ↔ 0.0/0.0) и
  синхронно `Head` (0.82 ↔ 1.72) в `tools/build_bench.py` → `bench.tscn`.**
  Ориентир: при конвенции «ноги в нуле» форма обязана быть в +0.9, при
  «центр в нуле» — в 0.0, а `eye_height_stand` =Head.y.

## Раунд 2 — «меню кривое, веб чёрный, exe вылетает» (14.09)

Три дефекта, все — по замеру и логике, не по картинке (GPU в песочнице нет):

1. **`.exe` падал через ~10 с после старта.** Сцена несла `directional_shadow
   max_distance=140` + **6 источников с тенями** (5 кубатурных оммни + солнце) +
   `positional_shadow_atlas` на дефолтных 4096. На встроенном/слабом GPU это
   переполнение VRAM и зависание драйвера. Исправлено: теневой бюджет в
   `scripts/core/boot_settings.gd` (`_apply_lights`), атлас позиционных теней ужат
   до 1024 в `project.godot`, MSAA 3D обнулён, кубатура 512, солнце 2048.
2. **Веб — чёрный экран при живом HUD.** SDFGI + volumetric fog + SSR на WebGL не
   поддерживаются. Новый автозагрузчик `Boot` (boot_settings.gd) определяет
   рендерер (webgl/gl_compatibility/forward_plus) и на WebGL/совместимом режиме
   выключает SDFGI/volumetric/SSR/glow, включает прямой ambient + фон-цвет — кадр
   не чёрный. Переключатель «ГРАФИКА» в меню + F3-оверлей (fps/player/scene).
3. **Меню «кривое».** Вёрстка была на «всё в VBox, offset_right=-420» — на 16:9
   элементы разъезжались по нижнему краю на всю ширину. Пересобрано: бренд слева
   (якорь 0), панель меню справа фиксированной ширины (якорь 1, offset_left=-404),
   живой 3D-фон через SubViewportContainer+SubViewport (раньше SubViewport не
   выводился вовсе: его контейнер стоял под Node3D и «растворялся»).

Сопутствующее: синхронизировал `tools/build_bench.py` с фактической картой
(скрипт+группа+spawn_path на Player, имя узла Camera3D, HUD-инстанс, толстый пол
extents=1.0 вместо 0.05 для CCD, один теневой оммни), убрал в контроллере
`_guard_above_floor` (страховка «глаза в полу → поднять», «унесло под карту →
вернуть на спавн»). В `main_menu.tscn`/`.gd` добавлен переключатель графики.

Проверено: ballistics 27/0, movement 22/0, bench PASS, play_session PASS,
menu_runtime PASS (по якорям, не по position), assets 179/183 (4 rooms/*_map.tscn
битые намеренно — Godot3-наследие), live-автопилот PASS без единого SCRIPT ERROR.
В экспорт-логе `door.gd`/`door_body.gd`/`door_sound.ogg` — НЕ fatal: битые
rooms/demo/doors из аддона не мешают пакованию, итог rc=0.
